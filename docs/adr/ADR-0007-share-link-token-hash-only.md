# ADR-0007 — ลิงก์แชร์เก็บแค่ hash ของ token · โชว์ token ดิบให้เจ้าของเห็นได้ครั้งเดียว

**สถานะ:** ✅ Accepted · 2026-09-29

## บริบท

S13/S14 (แชร์ลุค — ADR-0003 · ADR-0005 ผู้เรียกที่ 4) ต้องสร้างลิงก์ที่ "token เดาไม่ได้" ให้เพื่อนเปิดดูลุค
โดยไม่ต้องล็อกอิน schema เดิมตอนออกแบบ data model (`server/db/schema.ts`) เลือกเก็บ `token_hash` เท่านั้น
ไม่มีคอลัมน์เก็บ token ดิบ — ถ้า DB รั่วจะไม่มีใครเอา token ไปใช้เปิดลุคคนอื่นได้ตรง ๆ

แต่ flow diagram (`docs/design/my-twin-styles.drawio` หน้า 5) เขียนไว้ว่า กด "แชร์" ซ้ำที่ลุคเดียวกัน
"มีแล้วใช้ลิงก์เดิม" ซึ่งดูเหมือนจะบอกเป็นนัยว่าต้องโชว์ค่าลิงก์เดิมซ้ำได้ — ขัดกับการเก็บแค่ hash ตรง ๆ
เพราะไม่มีทางย้อนจาก hash กลับเป็น token ดิบได้

## ทางเลือกที่พิจารณา

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| เก็บ token ดิบ (plaintext) ในตาราง | โชว์ลิงก์เดิมซ้ำได้เสมอ | DB รั่ว = ทุกลิงก์แชร์ที่เคยสร้างเปิดได้หมดทันที ขัดกับเจตนาเดิมของ schema |
| เข้ารหัส token ด้วย secret แล้วถอดกลับได้เฉพาะโซนสิทธิ์พิเศษ | โชว์ซ้ำได้ + DB รั่วอย่างเดียวไม่พอ | เพิ่มความซับซ้อน ต้องดูแล key แยก ยังมีความเสี่ยงถ้า secret รั่วด้วย |
| **เก็บแค่ hash (เดิม) · โชว์ token ดิบให้เจ้าของเห็นครั้งเดียวตอนสร้าง** ✔︎ | ปลอดภัยสุด DB รั่วอย่างเดียวใช้ไม่ได้เลย · ตรงกับที่ schema ออกแบบไว้แต่แรก | กดแชร์ซ้ำ (มีลิงก์อยู่แล้ว) จะไม่มีค่าลิงก์ให้โชว์/copy ซ้ำ ต้องเพิกถอนแล้วสร้างใหม่ถ้าทำลิงก์เดิมหาย |

## การตัดสินใจ

- **คงการเก็บแค่ `token_hash` (SHA-256 ของ token 256 บิตแบบสุ่ม) ตามที่ schema ออกแบบไว้แต่แรก** — ไม่เพิ่ม
  คอลัมน์เก็บ token ดิบหรือทำ reversible encryption เพราะ token มี entropy สูงพอที่ SHA-256 ธรรมดา
  (ไม่ต้อง salt/pepper แบบรหัสผ่าน) ป้องกัน brute-force ได้อยู่แล้ว
- `POST /api/looks/[id]/share` คืน token ดิบ **เฉพาะตอนสร้างแถวใหม่จริง ๆ** เท่านั้น ถ้ามีลิงก์ที่ยังไม่ถูก
  เพิกถอนอยู่แล้ว (`revoked_at IS NULL`) จะคืนแค่ metadata (`createdAt`, `viewCount`) ไม่มี token
- หน้า S13 (`app/pages/looks/[id].vue`) เก็บ token ที่เพิ่งได้มาไว้ใน component state (ref) — อยู่ได้แค่ช่วง
  ที่หน้ายังไม่ reload/ปิด ถ้าปิดแอปแล้วกลับมาเปิดใหม่และลิงก์ยังไม่ถูกเพิกถอน จะเห็นแค่ metadata + ปุ่ม
  "เพิกถอนลิงก์" — ไม่มีช่องคัดลอก พร้อมข้อความอธิบายให้เพิกถอนแล้วสร้างใหม่ถ้าทำลิงก์เดิมหาย
- ตีความ flow diagram "มีแล้วใช้ลิงก์เดิม" ว่าหมายถึง **ไม่สร้างแถว share_links ซ้ำซ้อนสำหรับลุคเดียวกัน**
  (metadata เช่น `viewCount`/`createdAt` ยังคงต่อเนื่องจากแถวเดิม) ไม่ได้หมายถึงต้องโชว์ค่า token เดิมซ้ำได้

## ผลที่ตามมา

- ผู้ใช้ที่ปิดหน้า S13 ไปก่อนจะ copy ลิงก์ แล้วกลับมาเปิดใหม่ จะ **หาลิงก์เดิมที่เคย copy ไม่เจอ** ต้องเพิกถอน
  แล้วกดแชร์ใหม่เพื่อได้ token ใหม่ (พฤติกรรมเดียวกับ API key/webhook secret ของหลายบริการ)
- ไม่ต้องมี secret แยกสำหรับเข้ารหัส/ถอดรหัส token — ลดพื้นผิวที่ต้องดูแลความปลอดภัยเพิ่ม
- ถ้าในอนาคตอยากให้โชว์ลิงก์เดิมซ้ำได้จริง ต้องกลับมาแก้ ADR นี้และเพิ่มกลไกเข้ารหัสแบบย้อนกลับได้แทน

## ทบทวนเมื่อไหร่

ถ้าผู้ใช้จริงบ่นบ่อยว่าทำลิงก์หายแล้วรำคาญที่ต้องสร้างใหม่ — ค่อยพิจารณาเข้ารหัสแบบย้อนกลับได้
(ตัวเลือกที่ 2 ในตาราง) แทนการเก็บ hash เฉย ๆ
